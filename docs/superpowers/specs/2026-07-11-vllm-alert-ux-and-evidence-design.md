# vLLM 告警同步与证据增强设计

## 目标

解决告警完成入库后右侧“近期告警”不自动同步视觉分析结论的问题，并提升视觉模型对攀爬墙体、破坏设施等高风险行为的识别依据。

## 实时同步

围栏触发后，前端即时告警仍通过现有 WebSocket `frame` 消息显示，状态为“分析中”。两秒后，三帧采样和 vLLM 分析完成，后端保存告警记录后向同一视频源的 WebSocket 推送独立 `alert_ready` 消息。

该消息携带完整告警记录，包括数据库 ID、`vllm_analysis`、`vllm_risk_level` 和 `vllm_is_destructive`。前端收到后按 ID 或触发关联信息替换“分析中”的即时项，并更新右侧近期告警。这样右侧不依赖一次可能早于入库的历史接口查询。

## 视觉证据

每次 vLLM 请求发送六张按时间排序的图像：

1. 三张原始全景帧：触发前 2 秒、触发时、触发后 2 秒，用于识别围栏、墙体和场景变化。
2. 同一时间点的三张目标裁剪帧：由告警 bbox 扩展固定边距后裁剪，用于识别人体姿态、手部接触、跨越和工具动作。

若 bbox 无效或裁剪面积过小，只发送全景三帧；调用接口仍接受任意数量的图像，以避免放大无效像素。

## 结构化风险结论

提示词要求模型仅输出 JSON 对象：

```json
{
  "risk_level": "high | review | low",
  "is_destructive": true,
  "evidence": "基于哪几帧、目标姿态和与设施的交互的具体观察",
  "uncertainty": "遮挡、距离、画面范围等限制"
}
```

规则：观察到翻越姿态、跨越围栏/墙体、持续拉拽、撞击、拆卸或破坏设施时为 `high`；证据不足、目标被遮挡或关键设施不可见时为 `review`；只有明确可见的正常通行或与设施无交互才为 `low`。禁止以“无法确定”为由返回低风险。

客户端解析 JSON；服务返回非 JSON 或字段无效时，保存原文本至 `vllm_analysis`，风险等级为 `review`，避免静默降级为低风险。

## 数据与前端

`Alert` 增加 `vllm_risk_level`（`high`、`review`、`low`）与 `vllm_is_destructive`。API、WebSocket 和 TypeScript 类型均返回这两个字段。右侧近期告警和告警历史详情显示风险标签、模型结论及证据，分析中状态不会阻塞首次围栏提示。

## 失败策略与测试

vLLM 不可用、超时、图像编码失败时，原告警仍保存并通知；风险等级为空而非人为判断。新增单元测试覆盖 bbox 裁剪、六图请求顺序、结构化结果解析、非 JSON 回退和 `alert_ready` 消息构造。前端构建与后端测试用于验证消息类型和字段传递。
